## Fixed

- **Results disappearing during a fix.** Starting another run could clear the
  displayed results before the engine rejected the overlapping request. Both
  views now keep new runs and view switches disabled until the fix and its
  re-check finish. Restart controls use the same guard.
- **Stale post-fix reports.** A re-check now refreshes the live report's
  comparison, diagnosis, verdict and displayed log together. The saved original
  remains in History. Failed re-checks show a clear message and release the
  controls instead of leaving “Re-checking…” on screen.
- **Simultaneous saves overwriting reports.** History filenames are claimed
  atomically, so two runs saved in the same second keep separate records.
  Concurrent index writers also use separate temporary files.
- **History missing quick edits.** The cache now detects same-size edits within
  one second, keeping History and Trends current while retaining cached reads.
- **Lost undo settings after a partial tune-up.** Retrying the TCP and adapter
  power step now preserves the full original snapshot, including settings the
  first attempt already changed.
- **Malformed destinations accepted silently.** Empty port lists, conflicting
  port specifications and text after a bracketed IPv6 address are rejected.
  The browser preview follows the same rules.
- **Unreported self-service save failures.** The person running a computer check
  is now told when its report could not be saved to History.

## Regression coverage

- 199 core tests on Linux and 197 on Windows, including concurrent saves,
  same-size history edits and report refreshes.
- Six browser tests against the real frontend with simulated checks and repairs.
- Workspace Clippy with warnings denied, read-only diagnostics, previews and
  site-profile smoke checks on Windows and Linux.
- Windows MSI and setup installers and the Linux Debian package, with checks
  that their license files are included.

The browser suite now runs in CI before installer packaging. Node.js is needed
only to run these optional development tests; the app still uses static
frontend files. Real domain and hardware-dependent repair validation remains
as described in the README.
