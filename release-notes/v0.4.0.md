## What's new

- **Site profiles.** One TOML file says what a machine needs (services, apps with minimum versions, servers, devices), which fixes are allowed, whether installs are locked, which view it opens in, and which KB articles go with which problems. A broken machine-wide profile makes itriage read-only instead of ignoring the policy. Examples are in `profiles/`.
- **Workstation checks.** Clock drift (measured over SNTP), domain sign-in and Group Policy, printers and stuck queues, Device Manager problem codes, Wi-Fi signal and VPN, expiring machine certificates, and battery wear.
- **Site checks.** Required and clinical apps with minimum versions, required services, and servers that must answer.
- **One-click fixes.** Restart the print spooler, clear a stuck queue, resync the clock, refresh Group Policy, start a service, flush DNS. Each asks first, is checked against the site policy, re-checks afterwards, and is written to the audit log and the Windows event log or syslog.
- **Run history and compare.** Every run is saved, and the next run on that machine shows what's new, resolved or changed. Reports from other machines open too, including the command-line `--json` output.
- **Ticket exports.** Plain text, rich text for TeamDynamix and Outlook, Markdown, and JSON.
- **Self-service view.** A calm page for end users: their computer name with a copy button, one button to check, results in plain words, safe fixes, and "Copy details for the service desk".
- **Cancel.** Long runs stop at safe points: between modules, and between Windows Update downloads.
- **Fixed.** Windows Server shows its real edition name, and event-log details are no longer cut off at the first line.
