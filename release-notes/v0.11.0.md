Three things that widen who can use ITriage: sites can write their own checks without waiting for a release, an AI assistant can run the read-only checks and explain them, and the console works with a keyboard alone, a screen reader, reduced motion and Windows contrast themes. Includes everything in v0.10.2.

## Site custom checks

Every site has a few things ITriage can't know to look for: the badge-tap agent should point at the production appliance, a printer-mapping script should have run this week, nobody should have signed in with a temporary profile today. A `[[check]]` in the site profile now describes one of them, and the new **Site custom checks** module (`site.rules`) runs them.

```toml
[[check]]
label = "Badge-tap agent points at production"
kind = "registry"
key = 'HKLM\SOFTWARE\SSOProvider\ISXAgent'
value = "IPTXPrimServer"
equals = "imprivata.example.org"
severity = "critical"
help = "This PC is pointed at another appliance. Reinstall the agent from Software Center."
```

- **Six kinds.** `registry` (a key, or one value of any common type), `file` (present, contents, version resource, how recently it changed), `service` (Windows service or systemd unit), `process` (a running program), `event` (event IDs in a Windows log over the last hours) and `journal` (a unit's journal entries on Linux). Each takes one condition: `exists`, `equals`, `contains`, `matches`, `min`/`max`, `min_version`, `state`, `max_age_days` or `max_count`. `severity` grades a failure and `help` is shown under it.
- **Nothing runs.** No kind executes a command or a script: a profile can make ITriage look somewhere, never do something. Event-log queries are built only from numeric IDs and from log and provider names limited to letters, digits, spaces and `-_./`.
- **Bounded.** At most 100 checks, 20 event IDs each and 30 days back; files are read up to 1 MB (UTF-8 or UTF-16); patterns are compiled with size limits.
- **A typo stays local.** A check that's written wrong is a warning on its own row saying what's wrong, and the rest still run. It doesn't make the profile invalid, which for a managed profile would lock ITriage read-only.
- **No false all-clear.** On Linux, a journal that records nothing, or one this account can only partly see, is "couldn't check" rather than "none".
- A failed `service` check that expected `running` offers **Start service**, under the profile's fix policy as usual.

Both shipped profiles have examples, and the README lists every setting.

## Read-only checks for AI clients (MCP)

`itriage --mcp` serves the read-only checks to an AI client over the [Model Context Protocol](https://modelcontextprotocol.io/), so an assistant can run them on the computer in front of the technician and explain what they found. Add it to any MCP client that starts local servers:

```json
{ "mcpServers": { "itriage": { "command": "C:\\Program Files\\itriage\\itriage.exe", "args": ["--mcp"] } } }
```

- **Three tools.** `list_checks`, `run_checks` (check ids and/or a preset, an optional destination and ticket; the report as text plus a structured copy with each finding and the likely cause, with progress per check) and `recent_runs`.
- **Nothing that changes the machine is reachable.** Modules that change anything aren't listed and are refused by id, presets that contain one aren't offered, there's no tool for fixes, and every run is made in preview and remote-safe mode as well.
- **Pseudonymized by default.** Before anything leaves ITriage it goes through the case bundle's redaction: host, account and domain names and addresses become stable placeholders. `[mcp] redact_terms` adds words of your own. If redaction can't be done, nothing is sent.
- **Findings are data.** Every result says that text quoted from the computer (event messages, process and file names) is data, not instructions.
- **Audited.** A run is saved and audited like any other, plus one `mcp` line (event 1200) per call naming the client as it describes itself.
- **The site decides.** `[mcp] enabled = false` turns the server off; `[mcp] checks` limits what it offers.
- It speaks both generations of the protocol: the stateless 2026-07-28 revision and the `initialize` handshake of 2025-11-25 back to 2024-11-05. No new dependencies.

## Accessibility

- **Keyboard.** Skip links to the checks and the results. Each check is ticked with Space or Enter on its box, with the focus ring round the row. Dialogs keep Tab inside them (the console behind is inert) and put focus back on the button that opened them. The Export menu takes the arrow keys, Home and End.
- **Screen readers.** Check boxes are labelled by the check's title and described by what it looks at and its last result. Every finding says its severity in words. The start and end of a run, and the self-service verdict, are announced once each. The progress bar is a real progress bar, the destination field is its own control, and both views have a heading and landmarks.
- **Not colour alone.** Severity has a shape too: a dot is OK, a ring is information, a triangle a warning and a diamond critical.
- **Contrast.** On the main screen, text in every theme now measures at least 4.5:1 against what's painted behind it. Each theme's dim text is a little brighter, the faintest labels moved up to it, and Sleek Minimalist and Enterprise Glass use a darker red behind white button text.
- **Reduce motion** in the theme picker, alongside the computer's own setting.
- **Windows contrast themes.** Switches, ticked boxes, the progress bar and severity shapes keep their state when Windows replaces the console's colours.

## Upgrading

Nothing in an existing site profile needs to change. `[[check]]` and `[mcp]` are new and optional; without them the new module says the profile has no custom checks, and `--mcp` runs with redaction on. SIEM rules for ITriage's events keep working; event 1200 is new.

On Linux also: a ping answered and a second run refused mid-run, the host name replaced with a placeholder, and the audit log's lines.
- **Accessibility:** axe-core finds nothing in the console (before and after a run), four dialogs or the self-service view. Browser tests drive the skip link, ticking a check from the keyboard, Tab staying in a dialog and focus coming back, the Export menu's keys, the severity words, the run announcement, the motion switch and a forced-colours page. Contrast was measured in all nine themes.
