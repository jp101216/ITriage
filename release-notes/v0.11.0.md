## New checks

- **Outlook, Teams & OneDrive** (`desk.m365`, Windows). Read for the person at the console, from their own profile and registry hive, even when ITriage runs elevated as someone else.
  - Outlook data files (`.ost`, `.pst`) against the limit a policy sets (`MaxLargeFileSize`, `WarnLargeFileSize`) or Outlook's own 50 GB and 47.5 GB. A full file is critical: Outlook stops adding mail to it.
  - The Microsoft 365 Apps version, its update channel (named from Microsoft's channel GUIDs) and platform. When the site profile requires Office with a `min_version`, an older install is a warning.
  - Desktop, Documents and Pictures moved into OneDrive while OneDrive isn't running. Nothing in them is syncing then, so nothing is backed up.
  - The new Teams cache size, with a **Clear Teams cache** fix, and a leftover classic Teams folder.
  - The Entra sign-in broker (Microsoft.AAD.BrokerPlugin), and errors in the AAD/Operational log over 24 hours, linked to Microsoft's primary refresh token troubleshooting article. A few errors a day are normal, so it warns only at ten.
  - It joins the sign-in runbook.
- **Edge IE mode site list** (`desk.browser`, Windows). Edge's `InternetExplorerIntegrationLevel` and `InternetExplorerIntegrationSiteList` policies. The site list is fetched from its web address or file share and read; an older version 1 list is reported as legacy. Then it says which of the site profile's application URLs (and the target) open in IE mode, by the most specific matching entry. Three cases are warnings:
  - The list can't be fetched. Edge keeps its last copy, so this is a warning, not critical.
  - The list is empty.
  - The list is set while IE mode is off, so Edge ignores it.

  The slow-app runbook uses it on Windows.

## Changed checks

- **Printers & print queue: Point and Print.** This covers who may install printer drivers (administrators only, Windows' default since 2021, or opened up, which is a warning or critical). It also shows the approved print servers and package print servers, and flags each connected printer's server that isn't on them. When only package Point and Print is allowed, drivers that aren't package-aware are flagged. Under Windows protected print mode, drivers that won't load are flagged. Policy is read from the computer, then from the signed-in person's hive.
- **Devices & peripherals: USB power saving.** USB selective suspend in the active power plan (plugged in and on battery), and each required USB device's own settings (selective suspend, enhanced power management, idle power-down). A setting a policy controls is labelled as such.
- **Recordings mark device drops.** While a recording runs, the devices the profile requires (`[[require.device]]`) are watched. On Windows that uses device notifications; on Linux, kernel uevents. The device list is also re-read every three seconds as a backstop. Each drop and return is a marker with its time, so it lines up with the samples in the CSV and the case log. The result gets a **Peripheral dropped** row per device, with how many times and whether it came back.

## New fixes

- **Clear Teams cache** (`clear-teams-cache`). Empties new Teams' cache folder for the person at the console, as Microsoft's article describes. It refuses while Teams is running in their session. The preview shows the folder and its size. The finding warns that clearing the cache also deletes Teams' diagnostic logs, so it's not the fix for missing messages.
- **Keep USB devices awake** (`keep-usb-awake`), **opt-in**. Turns USB selective suspend off in the active power plan, plugged in and on battery, after saving what it was. It costs some battery, so it's offered only when the site profile's `[policy] fixes` list names it, even in a profile with no list at all. It refuses when a policy sets the value, because the policy would undo the change.
- **Restore USB power** (`restore-usb-power`). Puts the saved values back. The saved file is checked before it's acted on: it must hold a plan GUID and on/off values.

## Likely cause

New rules name:

- a full Outlook data file;
- a missing sign-in broker, or repeated Entra errors (the "Need password" loop);
- Desktop and Documents in OneDrive with OneDrive not running;
- an IE mode site list Edge can't get;
- a print server that isn't on the approved list.

A required device that dropped during a recording is named too. When selective suspend is on, the next step points at it.

## What was and wasn't run

Everything here was built and tested on Linux and cross-compiled and linted for Windows. The grading, the site-list parser and matcher, the channel table, the drop tracker and the uevent parser are covered by unit tests. CI then runs it on a Windows Server 2025 runner.

None of the Windows reads (Outlook, OneDrive and Teams paths, Click-to-Run values, Edge policies, Point and Print values, power-plan values, device notifications) has been seen against a real clinical workstation yet. A server has no Outlook, Teams, scanner or USB power plan to look at. The steps for that pass are in `docs/ideas/next-features.md`.
