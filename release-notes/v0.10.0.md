Checks for the calls that fill a queue (an app that won't start, a slow sign-in, a "slow" laptop that's really being held back), for identity and trust, for the clinical desk (Outlook, Teams and OneDrive, Edge's IE mode site list, print drivers under Point and Print, the scanner that drops out), for the wall jack (wired 802.1X and NAC quarantine) and the Linux domain join, plus two ways to save time: watch mode for problems nobody is there to see, and a banner when a run matches a known incident.

## New checks

- **Policy blocks** (`sec.blocks`). "The Dragon plugin won't launch" and "Save to Documents fails" usually come from one block event, not from a setting. This names the rule that did it over the last seven days: Defender attack surface reduction rules (named from Microsoft's GUID table), Controlled folder access, antivirus detections, AppLocker and App Control (WDAC) on Windows; AppArmor and SELinux on Linux. Repeats of one rule on one file are one row, with how many times and when. A block in the last day on an app the site profile requires is critical. Audit-mode rules are information: they stopped nothing. Enforced blocks also appear in the change timeline, so `--problem-at` lines them up with the reported time, and the slow-app runbook checks them.
- **Sign-in speed** (`desk.logon`, Windows). "Please wait for the Group Policy Client", explained: the last sign-in's profile load and user policy as one total (against 60 s and 120 s, set with `[thresholds] logon_seconds`), each Group Policy extension's time, the ones that failed, how many GPOs applied, and a domain controller that didn't answer (1129) or a SYSVOL file that couldn't be read (1058) during it. It reads one sign-in's own events by their ActivityID, so background refreshes can't push it out of the log. The sign-in runbook uses it.
- **Throttling & hardware errors** (`system.hardware`). The processor's clock against its maximum right now, judged against how busy it is (low and idle is power saving; low and busy is a limit), the firmware's speed-limit reports (event 37) with the time spent limited, and corrected or fatal hardware errors (WHEA). On Linux: cpufreq, the thermal-throttle counters and EDAC. It joins the **Health check** preset and the slow-PC runbook. The live HUD sample and recordings now carry the clock too.
- **Outlook, Teams & OneDrive** (`desk.m365`, Windows). Read for the person at the console, from their own profile and registry hive, even when ITriage runs elevated as someone else.
  - Outlook data files (`.ost`, `.pst`) against the limit a policy sets (`MaxLargeFileSize`, `WarnLargeFileSize`) or Outlook's own 50 GB and 47.5 GB. A full file is critical: Outlook stops adding mail to it.
  - The Microsoft 365 Apps version, its update channel (named from Microsoft's channel GUIDs) and platform. When the site profile requires Office with a `min_version`, an older install is a warning.
  - Desktop, Documents and Pictures moved into OneDrive while OneDrive isn't running. Nothing in them is syncing then, so nothing is backed up.
  - The new Teams cache size, with a **Clear Teams cache** fix, and a leftover classic Teams folder.
  - The Entra sign-in broker (Microsoft.AAD.BrokerPlugin), and errors in the AAD/Operational log over 24 hours, linked to Microsoft's primary refresh token troubleshooting article. A few errors a day are normal, so it warns only at ten.
  - It joins the sign-in runbook.
- **Edge IE mode site list** (`desk.browser`, Windows). Edge's `InternetExplorerIntegrationLevel` and `InternetExplorerIntegrationSiteList` policies. The site list is fetched from its web address or file share and read; an older version 1 list is reported as legacy. Then it says which of the site profile's application URLs (and the target) open in IE mode, by the most specific matching entry. Three cases are warnings:
  - The list can't be fetched. Edge keeps its last copy, so this is a warning, not critical.
  - The list is empty.
  - The list is set while IE mode is off, so Edge ignores it.

  The slow-app runbook uses it on Windows.

## Identity and trust

- **Certificate revocation** (in Machine certificates). An expired CRL on the issuing CA breaks 802.1X, VPN and smart-card sign-in for every PC at once, and Windows' cache can hide it. For each machine certificate in use, the CRL is now fetched live from each HTTP distribution point (through the system proxy) and its next-update time checked: expired is critical, expiring within `[security] crl_warn_hours` (24 by default) a warning, unreachable a warning. The chain engine's own verdict sits beside it (revoked, offline, unknown). LDAP distribution points are left to the chain check. With failing 802.1X in the same report, the likely cause says so.
- **Kerberos tickets** (in Entra, Kerberos & SSO sign-in, now on Linux too). The ticket cache through LSA: the TGT and when it expires, service tickets, the KDC, and tickets still encrypted with RC4 (or DES), which Microsoft is removing from domain controllers. Servers that rejected a ticket (event 4, KRB_AP_ERR_MODIFIED, a duplicate SPN or stale password) are critical. Tickets belong to a sign-in, so they're only read when ITriage runs as the signed-in user, unelevated; otherwise it says so rather than reporting the administrator's. On Linux: MIT `klist -e`.
- **Fix previews.** `itriage --fix ID --what-if` says what a fix would do here and changes nothing, after the same policy checks a real run makes. The confirmation dialog shows it too (the Kerberos fix says how many tickets it would clear).

## Network and domain

- **Wired 802.1X & NAC** (`net.wired-auth`, Windows). It covers PCs on wall jacks behind ISE or ClearPass:
  - **The Wired AutoConfig service.** Stopped is a warning on a PC that used 802.1X in the last day.
  - **The last day of Wired-AutoConfig events.** The latest outcome, with the failure's reason and any certificate error it carries (revoked, revocation offline, expired, untrusted root). It also shows failures before a success, and attempts Windows suspended after failures.
  - **Each wired port's state** from `netsh lan show interfaces`. netsh is localized, so this is English only, and the events stay the source of truth.
  - **A NAC quarantine.** A wired address inside one of the profile's new `[network] quarantine_subnets` is critical: NAC put the PC in its remediation VLAN.
  - It joins the **Slowness triage** preset. The event IDs and field names come from the provider's own manifest, and the parser is tested against a real event and real netsh output.
- **Domain & Group Policy on Linux** (`desk.domain`). It reads:
  - the realm realmd joined;
  - as root, each SSSD domain online or offline with its active servers, and the machine account (`adcli testjoin`). No reachable domain controller is a warning; a failed test is critical;
  - the keytab's principals and KVNO, warning when it holds only RC4 keys;
  - `sssd.conf` not owned by root with mode 0600. That's critical, because SSSD refuses to start.

  The sign-in runbook checks it on Linux.

## Changed checks

- **Printers & print queue: Point and Print.** This covers who may install printer drivers (administrators only, Windows' default since 2021, or opened up, which is a warning or critical). It also shows the approved print servers and package print servers, and flags each connected printer's server that isn't on them. When only package Point and Print is allowed, drivers that aren't package-aware are flagged. Under Windows protected print mode, drivers that won't load are flagged. Policy is read from the computer, then from the signed-in person's hive.
- **Devices & peripherals: USB power saving.** USB selective suspend in the active power plan (plugged in and on battery), and each required USB device's own settings (selective suspend, enhanced power management, idle power-down). A setting a policy controls is labelled as such.
- **Recordings mark device drops.** While a recording runs, the devices the profile requires (`[[require.device]]`) are watched. On Windows that uses device notifications; on Linux, kernel uevents. The device list is also re-read every three seconds as a backstop. Each drop and return is a marker with its time, so it lines up with the samples in the CSV and the case log. The result gets a **Peripheral dropped** row per device, with how many times and whether it came back.

## Watch mode and known incidents

- **Watch mode** (`--watch`, off by default). For "it froze around 2 yesterday". Set `[advanced] watch = true` in the profile and run `itriage --install-watch` once as administrator (audited). It then starts at every sign-in as that user: a scheduled task for the Users group at below-normal priority on Windows, a systemd user unit on Linux.
  - **What it keeps.** The last ten minutes of samples, in memory.
  - **When it saves a capture to the user's run history:**
    - the processor stays above the CPU warning band for a minute;
    - the default gateway misses three pings in a row, once it has answered at all;
    - an application server from the profile refuses two TCP checks in a row;
    - Windows logs Application Hang 1002 or Application Error 1000.
  - **What a capture is.** The samples as a recording, with a marker at the moment, plus Top processes, Memory usage and Network connectivity. It also carries a row saying what watch mode does and doesn't collect. It's in History and the timeline, but never the run a later one compares with, and never a trend point.
  - **Limits.** One capture per 15 minutes at most. Old ones go by `watch_keep_days` and `watch_max_mb`, and ordinary runs are never touched. `--uninstall-watch` removes it.
- **Known incidents** (`[status] url`, managed profile only). Each run fetches the site's incident feed once, over HTTPS, and matches its incidents by module, a regular expression on the findings, and this PC's subnet. A match puts **Matches a known incident** above everything in the technician view and at the top of the text report and ticket text. A feed that can't be read is a quiet note.

## New fixes

- **Clear Kerberos tickets** (`purge-kerberos-tickets`). `klist purge` for the session ITriage runs in, or `kdestroy`. It refuses when elevated, as another user or as root.
- **Clear Teams cache** (`clear-teams-cache`). Empties new Teams' cache folder for the person at the console, as Microsoft's article describes. It refuses while Teams is running in their session. The preview shows the folder and its size. The finding warns that clearing the cache also deletes Teams' diagnostic logs, so it's not the fix for missing messages.
- **Keep USB devices awake** (`keep-usb-awake`), **opt-in**. Turns USB selective suspend off in the active power plan, plugged in and on battery, after saving what it was. It costs some battery, so it's offered only when the site profile's `[policy] fixes` list names it, even in a profile with no list at all. It refuses when a policy sets the value, because the policy would undo the change.
- **Restore USB power** (`restore-usb-power`). Puts the saved values back. The saved file is checked before it's acted on: it must hold a plan GUID and on/off values.

## Likely cause

The likely cause uses the new checks. A blocked app is named with the rule that blocked it. A slow sign-in names its slowest step ("Folder Redirection took 41.0 s of a 63.0 s sign-in"). A busy processor that's also being held back is reported as that, and the busiest program isn't blamed for it. It also names:

- a full Outlook data file;
- a missing sign-in broker, or repeated Entra errors (the "Need password" loop);
- Desktop and Documents in OneDrive with OneDrive not running;
- an IE mode site list Edge can't get;
- a print server that isn't on the approved list;
- a NAC quarantine;
- failing wired 802.1X, unless an expired revocation list already explains it;
- Wired AutoConfig stopped on an 802.1X PC;
- on Linux, an `sssd.conf` SSSD won't accept, a broken machine account, and a domain SSSD can't reach.

A required device that dropped during a recording is named too. When selective suspend is on, the next step points at it.

## The audit trail

- **Hash chain.** Each line of `audit.jsonl` carries the SHA-256 of the line before it, across rotation. `itriage --verify-audit` walks it and names the first line that was changed, removed or inserted (exit 1). Lines from 0.9 and earlier aren't chained and are counted separately.
- **Refusals have their own event**, 1102, apart from failures (1101). Each event's last line carries the ticket, the account and whether it ran elevated. The existing IDs (1000, 1001, 1100, 1101) are unchanged, so SIEM rules keep working.
- **The installers register the `itriage` event source**, so events render cleanly in Event Viewer from the first run, even one that never runs elevated. It's left in place on uninstall, so the events already logged stay readable.
- On Linux the copy goes to syslog through `syslog(3)` instead of running `logger`.
- `[audit] event_log = false` turns the system-log copy off, but only in a managed profile: a user's own profile can't hide what a technician did.

## Privacy

Case bundles now pseudonymize the user folder in the forms policy events write it (`%OSDRIVE%\USERS\NAME`, `\Device\HarddiskVolume3\Users\name`) and account SIDs.

## What was and wasn't run

Everything here was built and tested on Linux and cross-compiled and linted for Windows. The grading, the site-list parser and matcher, the channel table, the drop tracker and the uevent parser are covered by unit tests.

The Windows field names come from each provider's own event manifest, read on a Windows Server 2025 runner. The Defender test uses a real captured event. The ASR, AppLocker, App Control, Group Policy, processor-power and WHEA tests use events written from those manifests, not captures: those checks still need a pass on a real workstation (see the lab steps in `docs/ideas/next-features.md`).

On a Windows Server 2025 CI runner, these were seen working:

- Edge's version, read from its file version;
- USB selective suspend, read from the power plan;
- the Point and Print defaults;
- the AAD log;
- the wired check on a port without 802.1X.

Watch mode was run end to end there:

- the logon task was registered, read back and removed;
- a real Application Error 1000 produced a capture, and so did a busy processor;
- a gateway that never answers ping didn't.

On Linux, a busy processor produced a capture too.

The wired 802.1X parser is tested against a real Wired-AutoConfig event (15502) and real `netsh lan` output from a Windows Server 2025 runner. The success and failure events are written from the provider's manifest, because the runner's port doesn't ask for 802.1X. The Linux domain parsers are tested against real `sssctl domain-status`, `klist -k -t -e` and `adcli testjoin` output from an Ubuntu 24.04 runner with SSSD pointed at an unreachable domain controller. `realm list` printed nothing there, as it does on any PC realmd didn't join, so its parser follows realmd's documented layout. A joined machine still has to confirm it.

Some Windows paths haven't been seen on a real clinical workstation yet:

- Outlook, OneDrive and Teams, and the Click-to-Run values;
- an IE mode site list and Point and Print set by GPO;
- changing the power plan;
- device notifications with a real scanner;
- a real 802.1X success or failure;
- watch mode starting at an actual sign-in.

A server has no Outlook, Teams or scanner to look at. The steps for that pass are in `docs/ideas/next-features.md`.
