A bug-fix and hardening release, from a full review of 0.6.0. The first fix matters most: update before using **Install drivers & firmware** elevated.

## Downloads

| | File |
|---|---|
| Windows (setup) | `itriage_0.6.1_x64-setup.exe` |
| Windows (MSI, for SCCM / Intune) | `itriage_0.6.1_x64_en-US.msi` |
| Linux (Debian / Ubuntu) | `itriage_0.6.1_amd64.deb` |
| Checksums | `SHA256SUMS.txt` |

Every file has a SHA-256 in `SHA256SUMS.txt` and a build-provenance attestation: `gh attestation verify <file> -R jp101216/ITriage` proves it was built by this repository's Release workflow (see "Checking a download" in the README). If the Windows installers in this release aren't code-signed, SmartScreen says it "protected your PC": choose **More info → Run anyway**.

**Upgrading on Windows:** the setup now installs for all users under `C:\Program Files` (it asks for administrator rights). If you installed 0.6.0 or earlier with the setup, uninstall that copy first from **Settings → Apps**; it lives in your own profile and the new one won't replace it. The MSI is unchanged.

## Fixed

- **A one-click fix could start a real firmware run.** After a fix, ITriage re-checks the module the finding came from. On **Install drivers & firmware** that re-check ran the module for real, with no confirmation, even when the card came from a PREVIEW run: clicking **Install Dell Command | Update** went on to apply driver and BIOS updates. A fix now never repeats a change. A previewed module is re-checked as a preview, the results of a real run are left as they were, and the engine itself turns any re-check of a module that changes the machine into a preview, whatever the interface asks for.
- **System File Checker's output was lost.** `sfc` writes UTF-16 when its output is captured, and every one of its lines was mistaken for a progress redraw and dropped, so the log was empty and the result said only "done". UTF-16 output is now recognised and decoded, in any language.
- **An opened report could write files outside the history folder.** The saved file's name used the report's own date untouched, so a crafted report could name another folder. File names are now built only from letters, digits and hyphens.
- **Compare called problems "resolved" when a check couldn't run.** If a module failed this time, everything it had found last time was counted as resolved (and the other way round, as new). A module that couldn't run in one of the two runs is now listed under **Gaps** and its findings aren't compared.
- **The module list vanished in a small window.** At the 960×640 minimum the header and the rail's fixed parts left the checklist 40 px, less than one row. In windows under 840 px tall (a 1366×768 laptop is one) the telemetry strip is now one row, the header tightens, and module descriptions show two lines with the rest in a tooltip, so two to four modules are visible (two full rows in every theme at the minimum size). The default 1240×880 window looks exactly as it did.
- **Repair and update modules came back ticked.** The checklist remembers what was ticked last time; that included modules that change the machine, such as Restart the PC. Only checks are remembered now.
- **Restart Print Spooler failed when another service depended on the spooler** (Fax, LPD, some vendors' print services). Those are now stopped first and started again afterwards, and the result says which.
- **Lenovo runs always said "Restart required: no".** Thin Installer doesn't report it. ITriage now also asks Windows whether a restart became pending during the run, and when it still can't tell, says so and offers the restart.
- **Linux:** *Purge caches* said "flushed" even when the command failed, and *Restart adapters* could leave a device down if the session running it went over that device. It's now one request that NetworkManager carries out by itself.

## Safer with administrator rights

An elevated ITriage only starts programs, and only obeys a machine-wide profile, that a standard user couldn't have put there.

- **Windows' own tools** are started by full path from the system folder, never by bare name.
- **The manufacturer's update tool** is only run from a folder standard users can't write to. `C:\Program Files` passes. HP Image Assistant's default `C:\SWSetup\SP…` doesn't: ITriage says where the tool is and why it won't run it. Move it under `C:\Program Files\HP\HPIA`.
- **The tool's working folder** is made fresh for each run and locked to administrators.
- **A `profile.toml` that a standard user dropped into `%ProgramData%\itriage`** is ignored, with a warning in the header. Only one that administrators alone can change counts as the organisation's.
- **The Windows setup installs for all users** (see Upgrading, above).
- **Linux:** programs run as root come from the system's folders, not from `PATH`.

## Sturdier

- **BitLocker is suspended for one restart before the manufacturer's tool runs**, so a BIOS update doesn't leave the PC asking for its recovery key. If protection is on and can't be suspended, nothing is installed and the result says why. `[updates] suspend_bitlocker = false` in a site profile leaves it to the tool.
- **A hung command can't hold up a run.** Every external command now has a time limit.
- **A bug in one module doesn't end the run.** It's reported as that module's error, and the rest carry on.
- **Closing the window mid-run asks first:** keep running, or stop at the next safe point and then close. Relaunching as administrator is refused while anything is running.
- **Destination test:** a closed port is only critical when you typed that port. With none typed, the four defaults are tried and a closed one is information, so testing a web server no longer ends in ALERT over port 3389.
- **One ticket text.** The app now copies the engine's own rendering, the same text the command line prints and the history folder keeps.
- **History opens fast however many runs are kept.** The list reads a small index instead of every report.
- **Lighter telemetry.** Free space is re-read every 30 seconds, not every second; a network drive that has gone away can't stall the header.

The header also shows the full version (`v0.6.1`), so you can tell which build is on a machine.

## Testing status

- Automated tests: 151 on Linux and 146 on Windows (CI, Windows Server 2025); clippy clean on both. New ones cover UTF-16 output fed a few bytes at a time, history file names from hostile reports, a module that couldn't run in a comparison, command time limits, a module that panics, who may change a file (worked through for Program Files, a folder at the top of `C:\`, `%ProgramData%` and a user's own file), the managed-profile rule, BitLocker results, spooler dependents, the history index and destination grading.
- On Windows (CI, Windows Server 2025): the trust check is run against real files (a system tool passes, a file in the runner's temp folder doesn't), a folder is locked to administrators and read back, Windows' tools are found by full path, and every embedded PowerShell script is parsed.
- The fix path, the close prompt and the relaunch guard were driven in the real interface against a stand-in for the engine that records every command.
- All nine themes were measured at five window sizes. At 1240×880 every measured element is in the same place as in 0.6.0. No sideways scrolling and no console errors at any size.
- **Not yet run on real hardware:** the manufacturer tools, BitLocker suspension, the spooler restart with dependents, and NetworkManager reconnects. Their logic is tested and their Windows code is compiled and linted, but nobody has watched them work. Try them with PREVIEW first.
