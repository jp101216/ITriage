A pre-announcement review of 0.10.0: two security fixes for an elevated
ITriage, and four smaller fixes. Includes everything in v0.10.0.

## Security

- **Clear Teams cache could be pointed at another folder.** The fix empties the new Teams cache of the person at the console, and ITriage is often running elevated as a technician when it does. Every folder between that person's profile and the cache is theirs to replace, and the fix didn't check them: a junction there would have had an elevated ITriage delete whatever it led to. The fix now refuses when any folder on the way is a link or junction, names it, and says so in its preview. The check stops measuring and offering a cache it would refuse to clear. Clear temp files already worked this way.
- **`--install-watch` would register a copy of ITriage that others could replace.** Watch mode starts ITriage at every sign-in, as whoever signs in. Installed from a copy in a folder other people can write to (Downloads, a folder made at the top of `C:\`, a shared drive), that file could have been swapped for anything, which would then run as each person who signed in. It now refuses unless the copy is one only administrators can change (Program Files on Windows, `/usr/bin` from the `.deb`), and says where to run it from.

Neither needs a change to a site profile. If watch mode was installed from a portable copy, run `--uninstall-watch` and install it again from the installed one.

## Fixed

- **Clear temp files reported failures for folders that were never its to clear (Linux).** Another account's folder in `/tmp` (a service's, or one left by something run with `sudo`) was counted as "failed" with a Permission denied line, which turned a clean tune-up into a warning. Those folders are now left alone without comment, like other accounts' files already were.
- **Fix previews on Linux described changes that wouldn't happen.** `--fix ID --what-if` for a Windows-only fix (Group policy update, Clear Teams cache, Keep USB devices awake and six others) said what the fix does. It now says it would refuse, with the reason a real run gives.
- **Watch mode on Linux without `systemctl`.** A failed `--install-watch` left its unit file behind, and `--uninstall-watch` then couldn't remove it. A failed install now cleans up after itself, and the unit is removed whether or not `systemctl` can be asked to disable it first.
- **A short option after `--fix` was read as its target.** `--fix flush-dns -q` took `-q` for a target; `--verify-audit -q` took it for a file.

Smaller: watch mode's one-per-account lock recognises a running watcher by this program's own name rather than a fixed one, and the browser preview lists the checks in the app's order.

## Checked

Besides the automated tests, this review ran the published 0.10.0 installers: the checksums match, the `.deb` installs and its checks, history and audit log work, and the desktop app opens. On Linux it ran every read-only check as root and as an ordinary user, a recording and its case bundle, the timeline, baseline, trends and audit verification, every fix's preview, and watch mode end to end, including two watchers at once and installing from a trusted and an untrusted folder.

- 348 core tests on Linux and 20 browser tests, with workspace Clippy and the smoke checks on both platforms.
- New tests cover a Teams cache behind a link (the folder it leads to is untouched), a program others can replace, another account's temp folder, and the Linux previews.

The Windows side of the Teams cache fix is the same code the Linux tests exercise, compiled and tested on the Windows runner, but a real junction in a real profile hasn't been tried on a desktop edition of Windows. What 0.10.0 lists as not yet seen on a clinical workstation still stands.
