Two new checks, a guided workflow for a slow PC, and a pass over 0.8's investigation tools: what was wrong in them, and what made them hard to read. It includes everything in 0.8.0.

## Downloads

| | File |
|---|---|
| Windows (setup) | `itriage_0.9.0_x64-setup.exe` |
| Windows (MSI, for SCCM / Intune) | `itriage_0.9.0_x64_en-US.msi` |
| Linux (Debian / Ubuntu) | `itriage_0.9.0_amd64.deb` |
| Checksums | `SHA256SUMS.txt` |

Every installer has a SHA-256 in `SHA256SUMS.txt` and a build-provenance attestation; see [Checking a download](https://github.com/jp101216/ITriage#checking-a-download). The installers include `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt`.

## Fixed

- **The timeline lost what kind each event was.** On Windows, event times have seven decimal places, and a row read back from a report (for the Timeline dialog, `--timeline`, and a case bundle's `timeline.json`) came out as "Recorded event" whatever it was. On Linux the kind had a stray leading space. Times are whole seconds now, and reports saved by 0.8.0 read correctly too.
- **Installer and restart events said nothing.** Windows Installer and restart records carry their details without names, and servicing records carry them somewhere else again; all three were dropped, leaving "MsiInstaller event 1033". Rows are sentences now: "Installed Contoso Client 24.2.0.187", "Restart started by winlogon.exe for …: Operating System: Upgrade (Planned)", "Package KB5046617: Installed". Events from other sources in the Setup log are no longer filed under "Restart/boot".
- **A recording's first sample was made up.** It was taken microseconds after the counters were first read, so its CPU figure meant nothing (and could be reported as the recording's peak) and its disk and network rates were zero. The first sample now waits an interval, a second at most, like the rest.
- **Case bundles left Wi-Fi network names in.** The privacy pass looked for a finding called "SSID"; the Wi-Fi check calls it "Network". Network names are now replaced wherever they appear (the Wi-Fi check, Wi-Fi events, a recording's samples), and so are an account name written without its domain, the domain itself, the AD site and the domain controller's name.
- **Case bundles shredded what wasn't private.** `C:\Windows\System32` and registry keys were replaced as if they were accounts, a version such as `24.2.0.187` as if it were an address, and `8.8.8.8` along with everything else. Paths, registry keys, built-in accounts, versions and the public resolvers a check names itself are left readable. An address keeps what kind it is (`[private-address-2]`, `[public-address-1]`, `[link-local-address-1]`), so the report still says an adapter had a 169.254 address.
- **Application checks couldn't reach an IPv6 address on Windows.** `https://[fd00::10]/health` lost its brackets on the way to WinHTTP.
- **Dialogs taller than the window opened at the bottom**, with their title and first lines scrolled out of sight (Replay and Case bundle, on a laptop screen).
- **Working PC offered this PC's own reports** as the working example, with raw timestamps. It lists other PCs only, and says how to bring a report in when there are none.
- **The ticket text ran to hundreds of lines** when a run included the change timeline. Ticket text, Markdown and rich text keep a history check's newest eight rows (and anything flagged) and say how many they left out; the full transcript, the JSON and a case bundle keep every row.
- **Markdown and rich text exports left out the investigation**: the guided steps and their reasons, a recording's markers, and the working-PC differences. All three text exports carry them now, and the differences are named, not counted.
- Narrow windows: a long button label ran out of the Timeline dialog, and the replay table squeezed to a word a line. An application entry with no label had no name. An application run stopped part-way said it had tested every URL. A recording's peaks were being followed in Trends.

## New checks

- **What's using the space.** "The disk is full" is where the question starts. This adds up the places that fill a workstation: each profile and the folders inside it, an old Windows installation, the Recycle Bin, temp folders, update downloads, memory dumps, the page and hibernation files, and installed software. It says what can be done about each ("Disk Cleanup removes it; there's no going back to the old version afterwards"). It names folders, never files; doesn't follow links or leave the drive; counts cloud files that aren't downloaded as nothing; and stops after 25 seconds, saying what it didn't reach. People's folders are measured before installed software.
- **Startup & sign-in speed.** How long the last start took, against a threshold (60 s to the desktop is a warning, 120 s critical) and against this PC's own usual; what Windows recorded as slowing starts down, with how often and by how much; and what starts with the PC, including what's switched off. On Linux: `systemd-analyze` and the autostart folders. It joins the **Health check** preset.

The likely cause uses both. A full disk now cites what the space check flagged (or its biggest folder), and says to run it when it hasn't been. A slow start gets a line of its own, naming what held it up.

## A slow PC, guided

**Troubleshoot → The whole PC is slow** (`--runbook slow-pc`) checks load, memory, free space and startup speed, then the drive's health and recent changes. It only adds up what's using the space when the disk turns out to be the problem.

## Investigations, easier to read

- **Change timeline.** Each kind of change has its own query, so a week of device events can't push the updates out. Group Policy rows are startup and sign-in processing and errors, not every internal step (on the test server, 46 of the timeline's 54 rows were one start's). A burst of one kind, such as a cumulative update's packages or one `apt install`, is one row ("40 events until 12:03:57: …; and 37 more") that still matches an onset search anywhere in its span. In the dialog: local time, where each row sits against the onset ("12 min before"), its kind, and an **Everything collected** view.
- **Network authentication history.** Rows say what happened in Windows' own words, under a short name for the log (`Wi-Fi 8001`), with the reason fields underneath. Failures are flagged whatever level they were logged at.
- **Recordings.** Each Wi-Fi reading keeps its signal and access point, and moves between access points are counted. Replay draws CPU, RAM and signal with the markers, the moves and the failed connections on the chart, reads out the sample under the pointer, and can list the failed connections alone. Enter in the marker box marks the moment. The connection finding names what it was connecting to, and a target that never answered once is called that ("this isn't what comes and goes") in place of a list of every second. `recording.csv` gains the Wi-Fi columns and the markers.
- **Working-PC comparison** also covers proxy settings, where the clock comes from and its time zone, and the domain and AD site. It shows on the report once made.
- **Case bundles** build faster: each string is read once, however many identifiers there are. A case with 800 identifiers over 8,000 log lines went from 1.7 s to 0.06 s.

## Interface

- A **filter** beside All checks and Clear: type part of a check's name, what it looks at, its group or its code. `/` jumps to it and Esc clears it. Ticks aren't touched.
- A history check's card shows its newest twelve rows and folds the rest.
- The four checks 0.8 added have short codes and glyphs in the list like the others.

## New profile setting

| Setting | Default | |
|---|---|---|
| `[thresholds] startup_seconds` | 60 / 120 | seconds from power-on to a usable desktop (to sign-in on Linux) |

Nothing else in a profile changes. Both new checks only look, so no policy applies to them.

## Changed

- `recording.csv` has three more columns at the end: `wifi_signal_pct`, `wifi_access_point`, `marker`.
- A timeline row in `--timeline` output and `timeline.json` can have an `until` (the end of a burst), and `at` is always whole seconds.
- Pseudonyms in a case bundle are named for what they replace (`[serial-1]`, `[domain-1]`, `[private-address-1]`) where 0.8.0 wrote `[identifier-N]` and `[address-N]`.

## Testing status

- Automated tests: 252 on Linux and 249 on Windows (CI, Windows Server 2025), 19 in a browser against simulated checks; clippy clean on both platforms.
- **Run for real on Windows in CI**, elevated, on a workgroup server: both new checks, the reworked timeline and network-authentication history, the slow-PC runbook, and a recording with its CSV and case bundle checked file by file. What that run printed shaped the release: 46 of the timeline's 54 rows had been one start's Group Policy steps, and a server, which keeps no start times, was told its log "could not be found (0x80073A9F)". Both read properly now.
- **Run for real on Linux**: the same from the command line, and the desktop app itself, clicked through the filter, the new checks, the Timeline dialog, a recording with a marker, and its Replay.
- The filter was measured in all nine themes at five window sizes: one line, no sideways scrolling, no console errors.
- **Not yet run where it matters:**
  - **Start times on a desktop edition of Windows.** CI is a server, which doesn't record them. Reading them has only been tested against sample events written from Microsoft's layout, so the first run on a real workstation is the real test.
  - **Windows Installer, servicing and restart rows.** None occurred on the runner; the sentences are tested against sample events.
  - **Wi-Fi.** CI has none: Wi-Fi and 802.1X events, and signal and access-point moves in a recording, haven't been seen live.
  - **OneDrive Files On-Demand.** Cloud-only files should count as nothing in What's using the space; untested on a real profile.
  - As before: nothing was run on a domain, as a standard user on Windows, or under Constrained Language mode.

Both new checks only read, so the place to start is a run on one real workstation: Health check, then What's using the space.
