## New checks

- **Sign-in & account lockouts.** Is the signed-in account locked, disabled or about to need a new password, do its mapped drives' servers answer, and what on this PC keeps locking it. After a password change, anything still holding the old password keeps trying it. The check lists the holders it can see: credentials saved under the account's name, a disconnected session of the same person, services and scheduled tasks set up to run as them, and failed sign-ins to this PC in the Security log (as administrator). When nothing here explains a lockout, it says where to look next: the person's phone and other PCs, and event 4740 on the domain controller. A Microsoft Entra ID (cloud) account's state can't be read from the PC; the check says so and still lists what's on the PC.
- **Security posture.** BitLocker on the system drive, antivirus and how old its definitions are, EDR sensors, the firewall (critical when it's off for the network profile in use), Secure Boot, TPM, UAC, and who is an administrator of the PC.
- **Drive health & reliability.** Each drive's health, wear, temperature and uncorrected errors, and the last 30 days of blue screens (with stop codes and what each usually means), unexpected shutdowns, disk errors, and the apps that crash or hang most.

Two presets go with them: **Account lockout** and **Health check**. Both only look.

## New fixes

| Fix | What it does |
|---|---|
| **Remove saved credentials** | removes the Credential Manager entries saved under the signed-in account's name. Windows asks for the password the next time each is used |
| **Sign out the session** | signs out the person's disconnected session on the PC. Unsaved work in that session is lost |
| **Unlock the account** | clears the lockout. It needs an account that's allowed to unlock users |
| **Revert tune-up** | puts TCP autotuning and the adapters' sleep settings back to what they were before **TCP autotuning & NIC power** changed them |

The last three are only offered to technicians. The self-service view offers **Remove saved credentials**, which acts on the person's own.

Unlocking doesn't last while something still uses the old password, and the report says so: clear the sources first.

## Likely cause

Every report now opens with up to three lines saying what is most likely wrong, each with the findings it rests on and what to do next:

```
LIKELY CAUSE
- Weak Wi-Fi (42%) is the most likely reason for a slow or dropping connection.
    Because: Wi-Fi & VPN: Signal: 42% · weak; Latency & packet loss: Gateway 10.20.32.1 round trip: avg 38 ms
    Next: Move closer to the access point or use a wired connection, then run the triage again.
```

They come from a fixed list of rules, not a guess, so the same findings always give the same lines. A failing drive comes before a full one, and no network before slow DNS. They're in the app, the ticket text, Markdown, rich text and JSON, and they're worked out again after a one-click fix.

## Ticket numbers

Type the ticket beside the run options (`--ticket INC0012345` on the command line). It goes on the report, on the end of the saved file's name, into History, and into the audit log with the run and with every fix and change made during it. It isn't remembered between sessions.

## Trends

**History → Trends** (`--trends` on the command line) follows one measurement across a PC's saved runs: free space, disk latency, Wi-Fi signal, gateway round trip, uptime, blue screens, definition age, days until the password expires. Read it with a pointer or the arrow keys; the same numbers are there as a table.

## Undo for the tune-up

**TCP autotuning & NIC power** now saves the settings it's about to change. Its preview says what would be saved, and its result offers **Revert tune-up**. Running the tune-up twice keeps the first "before". The rest of the tune-up has nothing to put back: flushed caches refill, and a network stack reset can't be undone.

## Update notice

When a newer ITriage is out, the header shows an **UPDATE** tag that opens the release page. It doesn't download or install anything. The app asks GitHub for the latest version number once a day. Switch it off with `[updates] notify = false`; it's also off whenever a profile turns off public probes.

## New profile settings

| Setting | Default | |
|---|---|---|
| `[security] require_encryption` | unset | unset: an unencrypted laptop is a warning, a desktop only noted. `true`: critical everywhere |
| `[security] user_may_be_admin` | `true` | `false` flags a signed-in user who administers the PC |
| `[updates] notify` | `true` | the update notice |
| `[thresholds] definitions_age_days` | 3 / 7 | antivirus definition age |
| `[thresholds] password_expiry_days` | 14 / 3 | days until the password expires |

A profile with a `fixes` list must name the new fixes to allow them: `clear-saved-credentials`, `logoff-session`, `unlock-account`, `revert-tuneup`. The clinical example does.

## Also

- The history index is rebuilt once after upgrading (`index.v2.cache`); the reports themselves are untouched.
- Saved credentials are listed by name only. The secrets are never read.
- The new Windows checks get some facts from PowerShell, because nothing else exposes them. The scripts are fixed text compiled into ITriage. Where PowerShell is blocked, those checks say so and the rest of the run carries on.

## Testing status

- Automated tests: 196 on Linux and 194 on Windows (CI, Windows Server 2025); clippy clean on both.
- **Run for real on Windows in CI**, elevated, on a workgroup server: all three new checks, the account and lockout-policy reads, the saved-credential and session listings, the Security log query, the Defender, firewall, Secure Boot and drive queries, the tune-up's settings read, the two presets, a ticketed run and `--trends`. One finding from that run shaped the release: a drive at 72 °C was told to "plan to replace it", so a hot drive now says to check the cooling.
- **Run for real on Linux**: the same from the command line, and the desktop app itself, clicked through a ticketed run, History and Trends. Its update check asked GitHub, was told v0.6.0 and showed nothing; with a newer version recorded, it showed the tag.
- The interface was driven end to end against sample data, and measured in all nine themes at six window sizes: no console errors and no sideways scrolling. In the default theme the default window measures as it did in 0.6; in the wider-lettered themes the preset line is now one line, not two.
- **Not yet run where it matters most:**
  - **On a domain.** No test machine was joined to one. Reading an account from a domain controller, unlocking it, matching services and tasks to a domain account, and real 4625 events have tested logic and passing local-account runs, but nobody has watched them against Active Directory.
  - **The fixes that change something.** Remove saved credentials, Sign out the session, Unlock, and Revert tune-up's restore step were never run against real state.
  - **As a standard user on Windows.** CI runs elevated, so the fallbacks (BitLocker state without rights, hidden drive counters) weren't exercised.
  - **Under Constrained Language mode.** The scripts are written to work there; it wasn't tested.

Try the new fixes on a test PC first.
