A review of 0.10.1: five fixes, three of them for Linux sites. Includes everything in v0.10.1.

## Downloads

| | File |
|---|---|
| Windows (setup) | `itriage_0.10.2_x64-setup.exe` |
| Windows (MSI, for SCCM / Intune) | `itriage_0.10.2_x64_en-US.msi` |
| Linux (Debian / Ubuntu) | `itriage_0.10.2_amd64.deb` |
| Checksums | `SHA256SUMS.txt` |

Every installer has a SHA-256 in `SHA256SUMS.txt` and a build-provenance attestation; see [Checking a download](https://github.com/jp101216/ITriage#checking-a-download). The installers include `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt`.

## Fixed

- **Required apps with a package epoch were reported out of date (Linux).** Debian, Ubuntu and Arch write some versions with an epoch first: `2:3.8.2+dfsg-1`. The `2` was read as the major version, so a `[[require.app]]` with `min_version = "3.8"` flagged an up-to-date package as "needs 3.8 or later". An epoch now counts only when both versions have one, and two epochs still compare the way dpkg compares them.
- **The likely cause could name the wrong drive as nearly full.** With one volume at a warning and another critical, the headline took the critical severity but named whichever volume came first. It now names the fullest by severity, and the system drive on a tie.
- **`fileserver01:445:3389` was taken for a host name.** Ports typed with colons passed as part of the host and were tried with the default ports, so the Destination test reported a name that doesn't resolve. That destination, and a `%` on anything that isn't an IPv6 address, now get the usual error, which shows how to write the ports. The browser preview checks destinations the same way.
- **Updates with long package names weren't counted (dnf).** `dnf check-update` moves the rest of a row onto the next, indented line when a name doesn't fit its column, and Available updates skipped those rows. They're read as one row now.
- **"Stopped after 0m without finishing".** A tool stopped at a time limit under a minute (klist, dsregcmd, netsh and others have limits of 5 to 30 seconds) gave its limit as 0m. It now says "10 s". The firmware speed-limit row rounded the same way ("limited for 0m in total") and is fixed too.

None of these needs a change to a site profile.

## Checked

- 352 core tests on Linux and 345 on Windows, 20 browser tests, workspace Clippy, and the smoke checks and installer builds on both platforms.
- New tests cover each fix: two drives at different severities, epoch versions against minimums, wrapped dnf rows, colon-joined ports and IPv6 zones, and time limits under a minute.
- The epoch fix was checked against the package database of an Ubuntu 24.04 machine: `bison 2:3.8.2` against a minimum of 3.8 was flagged before and passes now, and `bsdutils 1:2.39.3` against 2.40 is still flagged.

What 0.10.0 lists as not yet seen on a clinical workstation still stands.
